# SPATIAL-PATTERN-AI (CANVAS)

![Main Hero](main_hero.png)

> 텍스트를 256×256 픽셀 격자 위의 밝기 패턴으로 변환하여 학습하는 공간 패턴 기반 AI 엔진.
> 언어를 토큰 벡터가 아닌, 영상 프레임처럼 취급합니다.

```
 "귀여운 고양이가 밥을 먹는다."     256×256 격자 (1절 = 1타일)
         │                        ┌────────────────────────┐
    UTF-8 바이트                   │  ·                     │
         │                        │    ·  ·                 │
   ┌─────▼──────┐                │  · · ·  ·   ·          │
   │  X = 바이트값│                │     ·    ·              │
   │  Y = 위치   │   ──────►     │  ·    ·                 │
   │  밝기 = 가중치│               │       ·  ·             │
   └─────────────┘                └────────────────────────┘
                                   A채널: 빈도 히트맵
```

## 동작 원리

### 1. 3-레이어 비트맵 합산

![3-Layer Summation](visualization_1.png)

하나의 절을 3장의 독립 비트맵으로 인코딩한 뒤, 투명한 종이를 덧대듯 합산합니다.

```
  레이어       대상             가중치    포착 내용
 ─────────────────────────────────────────────────────
  기본         전체 바이트         +1     모든 바이트 위치
  단어         공백 기준 단어      +2     단어 단위 강조
  형태소       명사/동사/형용사... +1     언어 구조
 ─────────────────────────────────────────────────────
  합산 = 기본 + 단어 + 형태소       (최대 밝기 = 4)
```

```
  검증: "귀여운 고양이가 밥을 먹는다."
  ────────────────────────────────────
  기본 레이어:    40 px, 최대 1, 총  40
  단어 레이어:    37 px, 최대 2, 총  74
  형태소 레이어:  37 px, 최대 1, 총  37
  합산 (1장):     40 px, 최대 4, 총 151
                                     ↑
             보존 법칙: 151 = 40 + 74 + 37  ✓
```

### 2. RGBA 채널

```
  채널  │ 역할       │ 타입    │ 설명
 ───────┼────────────┼─────────┼──────────────────────────
   A    │ 밝기       │ uint16  │ 바이트 빈도 (3레이어 합산)
   R    │ 의미       │ uint8   │ 의미적 유사도 (AI 동적 매핑)
   G    │ 기능       │ uint8   │ 품사 / 문법 기능
   B    │ 확장       │ uint8   │ 컨텍스트, 시제, 감정
```

R/G/B 값은 **고정 테이블이 아닙니다** — AI가 방향성 확산을 통해 동적으로 매핑합니다:

```
  R ← 대각선 이웃 (↗↘↙↖)    α = 0.05   형태소/의미 관계
  G ← 수직 이웃   (↑↓)       β = 0.08   단어 대체 관계
  B ← 수평 이웃   (←→)       γ = 0.03   구/절 순서 관계
```

### 3. 멀티 타일 캔버스 (스케일링 구조)

각 절을 독립된 256×256 프레임으로 저장하는 대신, 최대 32개의 절을 하나의 **2048×1024 캔버스**에 8×4 타일 격자로 배치합니다:

```
  +-------+-------+-------+-------+-------+-------+-------+-------+
  |slot 0 |slot 1 |slot 2 |slot 3 |slot 4 |slot 5 |slot 6 |slot 7 |  y   0–255
  +-------+-------+-------+-------+-------+-------+-------+-------+
  |slot 8 |slot 9 |slot10 |slot11 |slot12 |slot13 |slot14 |slot15 |  y 256–511
  +-------+-------+-------+-------+-------+-------+-------+-------+
  |slot16 |slot17 |slot18 |slot19 |slot20 |slot21 |slot22 |slot23 |  y 512–767
  +-------+-------+-------+-------+-------+-------+-------+-------+
  |slot24 |slot25 |slot26 |slot27 |slot28 |slot29 |slot30 |slot31 |  y 768–1023
  +-------+-------+-------+-------+-------+-------+-------+-------+
```

캔버스 레이아웃의 장점:
- **경계 간 RGB 확산** — B채널이 인접 절 타일 경계를 넘어 수평으로 흘러, 각 절이 이웃 절의 맥락을 흡수합니다.
- **더 나은 RLE 압축** — 관련 절이 인접 타일에 배치되면 Y행이 연속적으로 동일해져 압축 효율이 높아집니다.
- **공간적 검색** — 쿼리 타일이 모든 슬롯과 비교되며, 이웃 타일의 R/G/B가 매칭에 반영됩니다.

### 4. 데이터 타입 자동 분류

절은 캔버스에 배치되기 전 자동으로 분류됩니다. 분류 결과가 슬롯 경계에서의 RGB 확산 강도를 결정합니다:

```
  DataType  │ 조건                        │ 경계 가중치
 ───────────┼─────────────────────────────┼────────────────
  PROSE     │ len > 150, 서술 텍스트      │ 0.5  (강한 흐름)
  DIALOG    │ len 30–150, 대화체          │ 0.3
  CODE      │ 특수문자 비율 > 15%          │ 0.1
  SHORT     │ len < 30, 단어/짧은 구절    │ 0.02 (독립적)
```

풀(pool) 내 캔버스는 **타입 동질성**을 유지합니다: 풀이 각 절을 동일한 타입의 캔버스로 라우팅하고, 슬롯이 없으면 새 캔버스를 생성합니다.

### 5. 매칭 파이프라인

타입 점프 단축 경로를 포함한 4단계 검색:

```
  입력 절
     │
     ▼
  ┌────────────────────────────┐
  │  3-레이어 인코딩             │
  │  + 방향성 RGB 업데이트       │
  │  + DataType 감지            │
  └───────────┬────────────────┘
              │
       ┌──────▼──────────────────────────────────────────┐
       │  Step 1: A-코사인 스캔 (동일 타입 슬롯)          │
       │  Step 2: R×G 스코어 (동일 타입 슬롯)             │
       │  Step 3: B×A 스코어 (동일 타입 슬롯)             │
       │  Step 4: 폴백 — 다른 타입 슬롯으로 확장         │
       └──────┬──────────────────────────────────────────┘
              │
        최적 (canvas_id, slot_id) + 유사도 %
```

평면 키프레임 인덱스에 대해서는 2단계 검색을 사용합니다:

```
       KF < 100: 전체 겹침 스캔 → Top-K → 코사인
       KF ≥ 100: 해시 버킷 → 겹침 → Top-K → 코사인
```

### 6. 키프레임 / 델타 저장

![Hierarchical Matching](visualization_2.png)

영상 코덱처럼: I-프레임(전체 스냅샷)과 P-프레임(변화량만 저장).
장면 전환 감지가 적응형 EMA 임계값(x264 방식)으로 프레임 타입을 결정합니다:

```
  캔버스 0: [I] "귀여운 고양이가 밥을 먹는다."   타입: DIALOG
  캔버스 1: [P] "귀여운 강아지가 물을 먹는다."   타입: DIALOG  (Δ16px)
  캔버스 2: [I] "def foo(): return 42"           타입: CODE
  ...
  캔버스 N: ∞ (캔버스 풀로 무한 확장)

  ┌─────────────────────────────────────────────────────────────┐
  │  변화 블록 ≥ 50% → 새 IFRAME (장면 전환)                   │
  │  변화 블록 <  50% → PFRAME (최적 참조 대비 델타)           │
  └─────────────────────────────────────────────────────────────┘
```

델타 항목은 자동으로 가장 작은 형식으로 저장됩니다:

```
  Sparse 형식 (6 B/항목): uint32 index + int16 diff_A
  RLE 형식    (8 B/항목): uint32 start + uint16 length + int16 diff
  → 쓰기 시점에 더 작은 쪽을 자동 선택
```

### 7. 서브타이틀 트랙 (SubtitleTrack)

캔버스 슬롯 위에 얹는 메타데이터 전용 인덱스 레이어 — 영상의 자막 트랙과 같습니다.
매칭 점수에는 영향을 주지 않으며, 쿼리가 **전체 슬롯을 스캔하지 않고 해당 DataType의 슬롯으로 바로 이동**하도록 안내합니다.

```
  SubtitleEntry { type, topic_hash, canvas_id, slot_id, byte_length }

  pool_match() 흐름:
    쿼리 타입 감지 →
    subtitle_track_ids_of_type() 조회 →
    A-코사인 → R×G → B×A → (폴백: 다른 타입)
```

### 8. 모델 I/O (SPAI v3 포맷)

추가 전용(append-only) 태그 레코드 형식의 바이너리 저장/로드:

```
  파일 헤더 (32 바이트):
    magic[4] = "SPAI"   version = 3
    kf_count  uint32    df_count  uint32
    reserved  3 × uint32

  레코드 태그:
    0x01  Keyframe  (327 752 바이트: id + label + A/R/G/B 격자)
    0x02  Delta     (가변: id + parent_id + sparse 항목들)
    0x03  ChannelWeights  (4 × float)
    0x04  Canvas    (전체 2048×1024 캔버스)
    0x05  SubtitleTrack
```

증분 저장(`ai_save_incremental`)은 새 레코드만 추가하며 기존 데이터를 덮어쓰지 않습니다 — 대형 모델에서도 안전합니다.

### 9. 생성 (Generation)

엔진이 학습된 패턴을 텍스트로 **역방향 디코딩**할 수 있습니다:

```
  ai_generate_next(input_text):
    1. input_text 인코딩 (3-레이어 + RGB 확산)
    2. match_engine → best_kf_id
    3. 다음 키프레임 = keyframes[best_kf_id + 1]
    4. grid_decode_text(다음 키프레임) → 출력 바이트
```

스코어링은 4개 채널을 모두 사용합니다 (SPEC §9.4):

```
  score(y, v) = A_sum[y,v]
              × (1 – |R_mean – in_R| / 255)
              × (1 – |G_mean – in_G| / 255)
              × (1 – |B_mean – in_B| / 255)
```

## 형태소 분석기

사전 기반 최장일치법. 외부 라이브러리 없이 동작합니다.

```
  입력                  결과
 ──────────────────────────────────────────────────
  "귀여운"          →  [형용사: 귀여운]
  "고양이가"        →  [명사: 고양이] + [조사: 가]
  "밥을"            →  [명사: 밥] + [조사: 을]
  "먹는다."         →  [동사: 먹] + [어미: 는다] + [구두점: .]
```

```
  사전 구성:
  ├── 명사  88개  (동물, 음식, 사물, 자연, 사람, 추상)
  ├── 동사  39개  (먹, 가, 오, 보, 하, 되, ...)
  ├── 형용사 20개  (귀여운, 예쁜, 밝은, 아름다운, ...)
  ├── 조사  26개  (은/는/이/가/을/를/에서/으로, ...)
  └── 어미  20개  (는다/었다/았다/겠다, ...)
```

## 기존 LLM과의 비교

```
                  기존 LLM                  SPATIAL-PATTERN-AI
 ─────────────────────────────────────────────────────────────
  인코딩       토큰 → 벡터 → 행렬        바이트 → 픽셀 → 256×256
  파라미터     고정 크기 행렬              무한 캔버스 스택
  컨텍스트     제한된 윈도우 (128K)        무제한 (디스크 한도)
  해석 가능성  불투명한 가중치             히트맵으로 시각 확인
  학습 방식    전체 재학습                 증분 델타 / 캔버스 추가
  저장 단위    —                          2 MB / 캔버스 (32절)
```

## 고유 특성

- **해석 가능성**: 히트맵을 열면 AI가 무엇을 기억하는지 눈으로 확인
- **무한 파라미터**: 캔버스가 쌓이므로 파라미터 상한 없음
- **무한 컨텍스트**: 디스크가 허용하는 한 무한 확장; 증분 저장으로 새 레코드만 추가
- **증분 학습**: 새 데이터는 델타 또는 새 캔버스 타일만 추가 — 전체 재학습 불필요
- **되감기/분기**: 델타 체인 역추적으로 학습 과정 추적 가능
- **타입 인식 라우팅**: DataType 분류로 산문·대화·코드·짧은 구절을 별도로 저장하고 검색
- **경량성**: 캔버스당 ~2 MB (32절), 엔진 코어 수 MB — Termux, 임베디드에서 동작
